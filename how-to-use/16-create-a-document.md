# Create a document from a brief or template

Use this for a standalone proposal, report, plan, learning guide, or brief. For software or operational documentation grounded in a codebase, use [Write or update technical documentation](10-document-a-change.md).

## Start with a brief

> Read skills/create-document/SKILL.md and follow it. Create a [document type] about [topic] for [audience]. Its purpose is [reader outcome]. Use [sources or facts]. Aim for [length/detail] and return [format]. Ask only about missing details that would materially change the document.

Example:

> Read skills/create-document/SKILL.md and follow it. Create a two-page project proposal for operations leadership about replacing our inventory spreadsheet. Use the attached notes only; mark missing cost or timing information instead of guessing. Return an editable document.

## Provide a template

Attach the template or give its path:

> Read skills/create-document/SKILL.md and follow it. Use the attached template to create a [document type] for [audience]. Preserve its headings, order, and styles. Base content on [brief or sources]. Flag placeholders and boilerplate that cannot be verified; do not invent facts to fill them. Return [format].

If the template and brief conflict, ask the agent to identify the conflict and clarify when it affects the result.

## Review

> Tell me which sources support the important claims, which template requirements you followed, what remains unknown, and what checks you actually performed on the file and formatting.

For prose improvement, see [Write or edit prose](17-write-and-edit-prose.md). A polished document is not proof that its claims are correct.

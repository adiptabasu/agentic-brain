# Concise

Use when the user asks for concise or shorter replies, fewer tokens, or invokes this skill by name.

For this conversation, put the answer first and remove filler, repetition, and unnecessary framing. Prefer short paragraphs; use lists only when they make choices or steps easier to scan. Keep language natural and readable.

Preserve facts, key reasoning, caveats, uncertainty, chronology, exact names, numbers, units, paths, commands, and quoted text. Ask focused questions when missing information materially affects the outcome. Keep safety guidance, approval boundaries, and evidence-backed claims intact. Clarity wins whenever further compression could change meaning or make the answer ambiguous.

This changes response style, not the work: do not skip analysis, verification, or necessary steps to save tokens. Do not shorten code, commands, or user-requested deliverables unless asked. Follow requested length and detail for documents, explanations, and other artifacts; keep only surrounding commentary concise.

Continue concise style in the current conversation until the user asks for normal detail or turns it off. A request for more detail overrides the mode for that response.
